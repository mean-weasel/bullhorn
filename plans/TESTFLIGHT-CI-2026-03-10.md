## Summary

Fully automated TestFlight deployments from GitHub Actions, replacing the previous manual/broken workflow that relied on P12 certificates, provisioning profiles, and `altool`.

---

## Changed Files

### 1. `.github/workflows/ios-build.yml` — Complete rewrite

**Before:** Manual code signing (P12 + provisioning profile) and `altool` upload. This approach required maintaining and rotating certificates as secrets, which is fragile.

**After:** Fastlane with automatic signing via App Store Connect API key. The workflow (named `iOS TestFlight`, job `Build & Upload to TestFlight`):

1. Checks out code, selects Xcode 16.2, installs Node 20 deps via `npm ci` (with npm caching), runs `npx cap sync ios`
2. Installs Ruby 3.3 + Bundler (with gem caching via `bundler-cache: true`, `working-directory: ios/App` so it finds the Gemfile)
3. Decodes the base64-encoded ASC `.p8` key from secrets into `~/.appstoreconnect/private_keys/AuthKey_{KEY_ID}.p8`
4. Runs `bundle exec fastlane beta` which auto-increments the build number, builds with automatic signing, and uploads to TestFlight

The workflow runs on `macos-15` with a 30-minute timeout, and uses a concurrency group (`ios-testflight`, `cancel-in-progress: true`) to prevent parallel builds from colliding.

### 2. `ios/App/App.xcodeproj/project.pbxproj` — DEVELOPMENT_TEAM fix

`DEVELOPMENT_TEAM` was set to `""` (empty string) in both Debug and Release configurations. Changed to `B3A6AN2HA4`. Without this, `xcodebuild` fails with "Signing for App requires a development team" — even with `-allowProvisioningUpdates`.

### 3. `ios/App/fastlane/Fastfile` — Fastlane beta lane

The lane first constructs an `app_store_connect_api_key` object from `ASC_KEY_ID`, `ASC_ISSUER_ID`, and the `.p8` key file path. This API key is passed to both `latest_testflight_build_number` and `upload_to_testflight` for authentication — it replaces the older session-cookie approach.

Next, `latest_testflight_build_number` (with `app_identifier: "to.bullhorn.app"`) + `increment_build_number` (targeting `App.xcodeproj`) auto-increment the build number before the build step. This queries App Store Connect for the highest existing build number for the specific app and increments by 1, so consecutive CI runs never collide. Also renamed `APNS_TEAM_ID` → `APPLE_TEAM_ID` for clarity (the GitHub secret name stays the same — it's mapped in the workflow env).

The `build_app` action targets `project: "App.xcodeproj"`, `scheme: "App"`, and passes `xcargs: "-allowProvisioningUpdates"` to allow Xcode to automatically download and update provisioning profiles during CI builds — required for automatic signing to work in a headless environment. It also specifies `export_options` with `method: "app-store"`, `teamID` from the `APPLE_TEAM_ID` env var, and `signingStyle: "automatic"` — these control the IPA export and ensure automatic code signing is used.

The `upload_to_testflight` action uses `skip_waiting_for_build_processing: true` so the CI job completes immediately after upload rather than blocking for 15-30 minutes while Apple processes the build.

The Fastfile also supports an `ASC_KEY_FILEPATH` env var override for local development (falls back to the `~/.appstoreconnect/` convention used by CI).

### 4. `ios/App/fastlane/Appfile` — Env var rename + app identifier

Sets `app_identifier("to.bullhorn.app")` and `team_id(ENV["APPLE_TEAM_ID"])`. Updated to use `APPLE_TEAM_ID` (mapped from the `APNS_TEAM_ID` secret in the workflow). Removed the misleading `REPLACE_WITH_YOUR_TEAM_ID` fallback.

### 5. `ios/App/Gemfile` — New

Pins fastlane `~> 2.225` for reproducible CI builds (currently resolves to 2.232.2). The workflow uses `bundler-cache: true` to cache gems between runs.

> **Note:** `Gemfile.lock` must be committed for `bundler-cache: true` to work (it uses the lockfile as the cache key). The lockfile has been generated locally but is currently untracked — it needs to be committed.

### 6. `.gitignore` — Fastlane artifacts

Added `ios/App/fastlane/report.xml` and `ios/App/fastlane/README.md` (auto-generated by fastlane, should not be committed).

## Trigger Strategy

The workflow triggers on pushes to `main` with path filters, plus manual dispatch:

```yaml
on:
  push:
    branches: [main]
    paths:
      - 'ios/**'
      - 'capacitor.config.ts'
      - '.github/workflows/ios-build.yml'
  workflow_dispatch:
```

**Rationale:** Bullhorn uses remote URL mode (`capacitor.config.ts` → `server.url: 'https://bullhorn.to'`, overridable via `CAPACITOR_SERVER_URL` for local dev). The iOS app loads its web content from the production server, not from a local bundle. This means changes to `src/`, `public/`, or `package.json` do NOT require a TestFlight rebuild — they're picked up immediately when the web app deploys.

Only changes to the native layer need a new binary:
- **`ios/**`** — Swift code, entitlements, pbxproj, Fastfile, Info.plist
- **`capacitor.config.ts`** — Plugin config, server URL, native behavior settings
- **`.github/workflows/ios-build.yml`** — The workflow itself

This avoids unnecessary TestFlight builds on routine web deploys while still catching any native-layer changes.

> **Edge case:** If a Capacitor plugin version changes in `package.json`, `npx cap sync ios` may produce different native output. Since `package.json` is not in the path filter, this would NOT trigger a rebuild automatically. For now this is acceptable — Capacitor plugin updates are infrequent and can be paired with an `ios/` change or triggered via `workflow_dispatch`. If this becomes a pain point, add `'package.json'` to the paths filter.

## GitHub Secrets Required

Four iOS-specific secrets, all verified present via `gh secret list` (the repo also has other secrets like `NPM_TOKEN` and `VERCEL_DEPLOY_HOOK_URL` used by other workflows):

| Secret | Purpose |
|--------|---------|
| `ASC_KEY_ID` | App Store Connect API key ID (`8USA7522X7`) |
| `ASC_ISSUER_ID` | App Store Connect Issuer ID |
| `ASC_AUTH_KEY_P8` | Base64-encoded `.p8` private key |
| `APNS_TEAM_ID` | Apple Developer Team ID (`B3A6AN2HA4`) — mapped to `APPLE_TEAM_ID` env var in workflow |
